## Getting Started

Before contributing:

1. Read the project's [README](README.md).
2. Review the [Code of Conduct](CODE_OF_CONDUCT.md).
3. Check existing issues and pull requests to avoid duplicate work.
4. Make sure you understand the project's structure and Packwiz configuration.

## Reporting Bugs

If you encounter a problem with EverSmooth Optimized:

1. Check whether the issue has already been reported.
2. Open a new issue using the appropriate bug report template.
3. Provide a clear and descriptive title.
4. Include the Minecraft version, modpack version, launcher, and relevant environment details.
5. Explain the problem and provide reproducible steps.
6. Attach relevant logs or crash reports when necessary.

Please avoid submitting incomplete or unrelated bug reports.

## Suggesting Improvements

Suggestions that improve performance, stability, compatibility, usability, or the overall experience are welcome.

When submitting a feature request:

- Explain the proposed improvement.
- Describe the problem it addresses.
- Explain its potential benefits.
- Include relevant examples or references when possible.

All suggestions are subject to review and may not necessarily be accepted.

## Submitting Changes

If you want to contribute changes:

1. Fork the repository.
2. Clone your fork locally.
3. Create a separate branch for your changes.
4. Make your changes while following the project's existing structure.
5. Validate your changes before submitting.
6. Commit your changes with a clear and descriptive message.
7. Push your branch to your fork.
8. Open a pull request against the original repository.

### Pull Request Guidelines

Every pull request should:

- Have a descriptive title.
- Clearly explain the changes.
- Include the reason for the changes.
- Reference related issues when applicable.
- Avoid unrelated modifications.
- Follow the project's existing conventions.

Pull requests may be reviewed, requested for changes, accepted, or rejected at the maintainer's discretion.

## Modpack Guidelines

When proposing or modifying mods, resource packs, or other components:

- Ensure compatibility with the targeted Minecraft version.
- Verify compatibility with the project's mod loader.
- Check required dependencies.
- Consider performance, stability, and compatibility implications.
- Respect the original author's licensing and distribution requirements.
- Provide reliable project and download references.
- Avoid unnecessary or redundant additions.

Every proposed component should provide a meaningful benefit to EverSmooth Optimized.

## Documentation Guidelines

When modifying documentation:

- Use clear and understandable language.
- Keep information accurate and up to date.
- Follow the existing Markdown formatting conventions.
- Avoid unnecessary duplication.
- Include relevant references where appropriate.

## Code of Conduct

All contributors are expected to follow the project's [Code of Conduct](CODE_OF_CONDUCT.md).

Respectful communication and constructive collaboration are essential to maintaining a welcoming project environment.

## Questions and Support

For questions, clarifications, or contribution-related discussions, use the official project communication channels.

Please keep discussions relevant to EverSmooth Optimized.
